The Nette adapter now integrates the typed, versioned translator core 3 with lazy sources, locale-scoped cache initialization and live catalogue replacement.

Requires PHP 8.4+, Nette 3.2 and `bckp/translator-core >=3.0 <4.0`. Core 4.x is explicitly excluded. Upgrade the adapter and core together; replace the old translation `path` configuration with a named `sources` map.

- Compiled PHP storage is bundled with core; no separate PHP-cache package is needed.
- Source services implement `TranslationSource` and provide typed messages plus a mandatory string version. They are instantiated only when a locale needs source verification or loading.
- Production version checking defaults to 1% at locale initialization. Debug checks every initialized locale; individual translations do not verify source versions.
- `forceRecompile(?string $locale = null)` refreshes the current or selected locale and updates existing Nette, core, Latte and form translator references.
- Locale resolvers receive `StringList`; locales are normalized to lowercase with hyphens.
- Latte and Tracy remain optional. Diagnostics show stored source versions, initialization status, missing messages and plural warnings.
- The standalone NEON source supports file translations and content-based version detection.

See the [adapter manual](https://github.com/bckp/translator-nette/blob/v3.0.0/README.md) and [core migration guide](https://github.com/bckp/translator-core/blob/v3.0.0/MIGRATION.md).

Validation: real Nette DI containers, Latte and HTTP integration, forced replacement with OPcache, PHP 8.4/8.5 tests, PHPStan 8, PER3 with tabs, Composer audit and API compatibility tooling. A clean production installation without development dependencies was also verified.
